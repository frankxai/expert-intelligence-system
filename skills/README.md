# Skills

A skill is a bounded operating procedure. Each one defines its inputs, process, output, quality gate, and writeback.

| Skill | Use it when | Primary output |
| --- | --- | --- |
| `expert-intake` | Starting or re-scoping the system | Intake card and one route |
| `discover-genius` | Representative corpus exists | Genius Map proposal |
| `reclaim-knowledge` | Knowledge is scattered | Reclamation Map |
| `distill-method` | Repeated decisions or frameworks exist | Method Map proposal |
| `build-evidence-map` | Claims must become traceable | Evidence Map |
| `customer-discovery` | Audience progress is unclear | Interview plan and learning ledger |
| `design-expert-offer` | Method, audience, and evidence are usable | Offer architecture |
| `create-first-asset` | The system needs a real proof task | One reviewed artifact |
| `build-expert-system` | Enough inputs exist to sequence the full cycle | System build plan and staged execution |

Run one skill at a time. `build-expert-system` orchestrates the sequence but does not bypass the gates inside the other skills.
