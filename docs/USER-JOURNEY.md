# User Journey

## First encounter

The user recognizes the problem: their intelligence is scattered, tacit, and difficult for people or AI to use consistently.

**Proof shown:** the real repository structure and an Expert Map, not an abstract AI promise.

## First commitment

The user chooses one intended outcome and supplies 3–5 representative sources.

**Success signal:** one dated artifact, not “set up my entire AI business.”

## First value

The system returns a corpus-grounded map with sources, confidence, tensions, rights, and one next move.

**Success signal:** the expert says “that distinction is accurate” and can point to what they will do differently.

## First activation

The map improves one real piece of work.

**Success signal:** a research brief, offer, lesson, chapter, customer plan, or workflow is measurably clearer, safer, or more useful.

## Trust expansion

The user adds more sources and specialist roles only after the first result.

**Success signal:** every new capability has a named input, output, gate, and writeback.

## Compounding

Customer language, corrections, cases, and research improve the explicit system.

**Success signal:** learning survives the chat and remains portable.

## Drop-off risks

| Risk | Design response |
| --- | --- |
| “This looks too technical.” | No-terminal starter and one first cycle |
| “I do not know what to upload.” | Representative five-source prompt |
| “Will AI steal or flatten my work?” | Private-by-default files, rights audit, no-clone language |
| “Is this just another second brain?” | Method, evidence, decisions, and activation as the differentiators |
| “I already use ChatGPT.” | Works inside current tools; improves the source and operating contract |
| “This is too much setup.” | One useful artifact before expansion |
