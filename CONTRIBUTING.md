# Contributing

Contributions are welcome when they make the system more usable, verifiable, portable, or honest.

## Good contributions

- clearer workflow gates;
- better accessibility for non-technical users;
- evidence and provenance improvements;
- tested compatibility with an AI workspace;
- transparent fictional examples;
- translations that preserve the method.

## Please avoid

- vendor-specific lock-in;
- scraped or unconsented personal data;
- fabricated success examples;
- “AI clone” claims;
- workflows that publish or contact people without a human gate;
- domain advice that lacks qualified review.

Open an issue before a large structural change. Pull requests should name the user problem, include a small verification note, and keep public examples fictional or explicitly licensed.
